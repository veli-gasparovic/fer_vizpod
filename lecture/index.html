Why · two ways to store an image

Raster stores pixels. Vector stores shapes.

2 min. Naming what they just saw. The same three shapes (a bar, a dot, a line), stored two ways.

  • Step 0: they look identical at this size. That's the trap.
  • Step 1, zoom in: the raster drops to 16 × 16 and you see the pixel grid: staircase edges, blurry anti-aliasing. The vector shows its geometry: corners, centre, radius, end points. Drag the resolution slider; hover a pixel.
  • Step 2, what is stored: raster = 4 bytes (R, G, B, A) per pixel, and nothing else; there is no "circle" in a PNG. Vector = three lines of markup, same size at any zoom. Hover a shape on the right: its line lights up.
  • Step 3, trade-offs: vector for charts, maps, text; raster wins for photos and for very many marks (we come back to that with canvas, slide 29).

In SVG, labels are real <text> nodes. You can select them, Ctrl-F them, index them, style them with CSS (dark mode, print), and expose them to screen readers with role, aria-label and <title>.

Why · browser technology and standards

Every plugin died. The standards didn't.

3 min. This timeline is itself a D3 chart. Step 0 is the whole argument at a glance: every plugin bar ends in a red ✕, every standard runs off the edge as an arrow. The steps then label the milestones row by row. Hover any bar or dot for details-on-demand; press X to show its bound data.

  • Step 1, standards on paper: SVG 1.0 is a W3C Recommendation in Sep 2001, but browsers lag. IE had VML; others needed the Adobe SVG Viewer plugin.
  • Step 2, the plugin era: prefuse (Java, 2005), Flare (Flash, Oct 2007). Interactive, but closed runtimes.
  • Step 3, browsers catch up: Firefox 1.5 (Nov 2005, native SVG subset), jQuery (2006), querySelectorAll in WebKit (Feb 2008), Chrome/V8 (Sep 2008), IE9 with native SVG (14 Mar 2011).
  • Step 4, the fall: "Thoughts on Flash" (29 Apr 2010), Adobe announces EOL (Jul 2017), Flash blocked (12 Jan 2021). Adobe itself: "Open standards such as HTML5, WebGL and WebAssembly have continually matured… and serve as viable alternatives."
  • Step 5, D3: v1.0.0 tagged 17 Feb 2011, still on v7 today (7.9.0, Mar 2024). The browser platform only became viable the same year D3 shipped. D3's bet (the 2011 paper): no scenegraph of its own, just "efficient manipulation of documents based on data".

Moral: proprietary runtimes get abandoned; standards accumulate.

What · the data join

Diff your data against the DOM

5 min, the most important slide of block 1. Top row: the data array. Bottom row: DOM nodes. Green = enter, grey = update, red = exit.

  • Step 1, key function on: add, remove, shuffle. Elements keep their identity and move (object constancy).
  • Step 2, key function off: join by index. Remove a random value and the last node exits while all the others relabel themselves. Shuffle and nothing moves; only the labels change. This is the bug students will write.
  • Step 3: the paper's relational algebra: enter = D ▷ N, exit = N ▷ D, update = D ⋈ N.
What · scales

A scale is a function from data space to visual space

4 min. Drag the domain handles (top), the range handles (bottom) and the value. The readout shows the function call. Steps walk through linear → inverted range (SVG's y-axis points down) → log → band → colour (range doesn't have to be pixels).

An axis is just "a scale, drawn". The visualization literacy point: whoever controls the domain controls the story.

What · from scales to a chart

Scales → axes → marks → shapes

4 min. One chart, built up a layer at a time. The code panel always shows the code for the current layer, with the real numbers.

  • Step 0, margins + scales: the plot area sits inside the margins. Point at the flipped y range: SVG's origin is top-left, y grows down.
  • Step 1, axes: an axis is a scale drawn into a <g>. Move the pointer over the plot: invert() runs the scale backwards (this is how brushing and tooltips find data).
  • Step 2, marks: the join from two slides ago, positioned by scale calls. Hover a circle; press new data.
  • Step 3, rescale: the domain animates to [0, 50]. Then grab the y axis and drag it up and down: marks and axis stay in sync because they share one scale. Same .transition().call(yAxis) as in your d3.html render().
  • Step 4, shapes: d3.line() / d3.area() turn the whole array into one path string. Toggle the curve. Next slide opens up that string.

How · real-time data join

Where are you? Tap on your phone.

Clearing the dots: "clear all dots…" in this presenter window's bottom bar (three clicks). It is not on the public slide.

3 min. x = JavaScript experience, y = dataviz experience. Each tap goes as a POST to a Cloudflare worker, which broadcasts all the points over a WebSocket to every screen. Each screen runs one data join keyed by timestamp.

Step 1: reveal the render function: enter (grow in), update (move), exit (shrink out), the same three sets as before the break, now driven by a network.

Step 2, where the data comes from: nothing is "loaded". Your phone sends a tap with an HTTP POST to a Cloudflare worker; this screen keeps a WebSocket open, and the worker pushes the whole array (as JSON) to every screen on every change. Every push makes the status dot ring and sends a green packet down the WebSocket arrow to "every screen", and the grey box logs it (time, number of points, bytes): tap again and watch it happen. Contrast with d3.csv(url): one request, one answer, done, which is what you use for a file that doesn't change (the stripes, the map).

How · live code, part 1

Stripes I: encode → make it responsive → details on demand

8 min. This is where most of the live typing happens. The steps are a safety net: if you make a typo, press → and the next step overwrites only its own chunk.

  1. Band scale: one band per year, grey rects. Hover with X: each rect has its {year, anomaly}.
  2. Diverging colour scale: scaleDiverging + interpolateRdBu. Ask: why is the domain reversed?
  3. Responsive: the fixed width/height get commented out and replaced by viewBox + preserveAspectRatio="none". Drag the stage's bottom-right corner to resize: no re-render, because it's vector. The payoff of the "why".
  4. Tooltip on pointerenter: details-on-demand (Shneiderman).
  5. Accessibility: role="img" turns the SVG into one picture for a screen reader; its children (and any per-stripe <title>) are skipped. So the aria-label carries the message with real numbers, and a visually hidden <table> (the same join, different elements) carries the data.

Wrap-up

Three things to keep

1

Visualization = mapping data to visual variables.

That mapping is a scale: domain → range.

2

The data join = diffing data against the DOM.

Enter, update, exit, and a key to keep identity.

3

Standards outlive abstractions.

Java applets and Flash are gone. SVG, CSS and the DOM are still here.
